# 공장 작업일지 도메인 학습

## 1. 학습 목적

실제 SMT 공정 데이터에 합성 한국어 작업일지를 결합하기 전에, 제조 현장에서 어떤 기록이 언제 작성되는지 이해하고 현실적인 데이터 단위와 생성 주기를 정한다.

공장의 작업일지는 하나의 문서가 아니다. 생산실적, 작업 전 점검, 교대 인수인계, 이상 발생, 정비, 품질검사 등 목적이 다른 기록을 통칭하는 경우가 많다. 따라서 모든 작업일지를 동일한 주기로 생성하면 현실성이 떨어진다.

## 2. 작업일지의 주요 종류와 작성 시점

| 기록 종류 | 주 작성자 | 작성 시점 | 일반적인 주기 | 주요 내용 |
|---|---|---|---|---|
| 작업 전 점검 기록 | 작업자·관리감독자 | 설비를 가동하거나 작업을 시작하기 전 | 매 작업 시작 전 또는 매 교대 시작 전 | 방호장치, 비상정지, 자재와 공구, 주변 위험요인, 설비 상태 |
| 생산 작업일지·작업실적 | 작업자·조장 | 작업지시 시작·종료 또는 수량 변경 시 | 작업지시·로트 단위, 시스템에 따라 실시간 입력 | 품목, 로트, 시작·종료 시각, 투입·생산·불량 수량, 설비, 작업자 |
| 교대 인수인계 기록 | 이전 교대 작업자·조장 | 교대 종료 직전과 다음 조 투입 시 | 교대마다 1회 | 진행 중 작업, 남은 수량, 설비 이상, 임시조치, 다음 조 확인사항 |
| 일일 생산보고·생산일보 | 조장·생산관리자 | 하루 생산 종료 또는 다음 날 집계 시 | 하루 1회 | 일일 생산량, 가동시간, 비가동시간, 주요 문제와 조치 요약 |
| 이상 발생 기록 | 이상을 발견한 작업자·조장 | 경보, 정지, 품질 이상 등을 발견한 직후 | 사건 발생 시마다 | 발생 시각, 관찰 현상, 설비·공정, 즉시조치, 재가동 여부 |
| 정비·보전 기록 | 설비보전 담당자 | 점검이나 수리 직후 | 고장 발생 시 및 예방보전 계획 주기 | 고장 증상, 원인 추정, 교체 부품, 조치, 정지시간, 확인 결과 |
| 품질검사 기록 | 검사원·품질 담당자 | 초품, 공정 중, 로트 종료, 조건 변경 후 | 검사계획·로트·변경점 단위 | 검사 항목, 측정값, 판정, 격리·재검·조정 조치 |

위 주기는 모든 공장에 동일하게 강제되는 단일 규칙이 아니다. 제조설비의 점검 항목·기준·주기·방법은 회사의 설비관리 규정과 공정 위험도에 맞춰 정하도록 되어 있다. 다만 안전보건공단의 위험성평가 지침은 일상작업은 매일 작업 전에, 정비·보수 같은 비일상작업은 해당 작업을 시작하기 전에 안전점검하도록 안내한다. MES 현장 적용 사례에서는 작업지시, 공정, 생산실적, 품질, 설비관리를 연결하고 생산실적 관리에 작업일지 입력 기능을 둔다.

## 3. 작성 주기를 이해하는 핵심 원칙

### 3.1 정기 기록

시간표에 따라 반복되는 기록이다.

- 교대 시작 전 설비·안전 점검
- 교대 종료 시 인수인계
- 작업지시 또는 로트 종료 시 생산실적
- 하루 종료 후 생산일보
- 회사 기준에 따른 일·주·월 정기점검

### 3.2 사건 기반 기록

정해진 시각이 아니라 사건이 발생했을 때 작성한다.

- 설비 경보 또는 비정상 정지
- 센서값의 평소와 다른 변동
- 자재 공급 불량이나 피더 걸림
- 노즐·컨베이어·검사장비 이상
- 조건 조정, 부품 교체, 재가동
- 품질 이상을 발견한 뒤 시행한 조치

이상 탐지용 작업일지에서는 사건 기반 기록이 중요하다. 그러나 실제 불량 판정이 끝난 뒤의 결함명이나 정답 라벨을 기록에 넣으면 데이터 누수가 생기므로 제외해야 한다.

## 4. SMT 공정에서 예상할 수 있는 기록 흐름

SMT는 인쇄회로기판에 솔더 페이스트를 인쇄하고, 부품을 배치하고, 리플로우 오븐에서 납땜한 뒤 검사하는 흐름으로 이해할 수 있다. 실제 라인 구성은 데이터 설명서를 확인해 확정한다.

예상되는 하루 기록 흐름은 다음과 같다.

1. **교대 시작 전**: 설비 전원, 비상정지, 노즐·피더, 자재, 온도 조건 등을 확인한다.
2. **작업지시 시작**: 제품·로트·설비·작업자와 시작 시각을 입력한다.
3. **생산 중**: 설비가 정상이라면 별도 긴 문장 없이 수량과 상태가 자동 또는 수기로 누적된다.
4. **이상 발생 시**: 관찰한 현상과 즉시조치를 짧게 기록한다.
5. **로트 종료 시**: 생산량, 불량 수량, 중단시간, 특이사항을 마감한다.
6. **교대 종료 시**: 미해결 문제와 다음 작업자가 확인할 사항을 인계한다.
7. **일 마감 시**: 여러 작업지시와 교대 기록을 생산일보로 집계한다.

## 5. 현장 문장의 특징

작업일지는 보고서형 장문보다 체크 항목과 짧은 메모가 많다. 실제 문장에는 다음 특성이 나타날 수 있다.

- 주어 생략: `2호기 재가동 후 이상 없음`
- 축약어와 현장어 사용: `노즐`, `피더`, `LOT`, `재투입`, `조건값`
- 시각과 조치를 함께 기록: `14:20 압력 변동 확인, 공급부 점검 후 재가동`
- 문장 종결 방식 혼합: `확인함`, `확인 완료`, `이상 없음`, `관찰 필요`
- 띄어쓰기·기호·설비 명칭의 표기 차이
- 정상 기록은 짧고 반복적이며, 이상 기록은 현상과 조치가 조금 더 구체적임

현실적인 합성 로그 예시는 다음과 같다.

- `A조 시작 전 점검 완료. 2호기 노즐 및 피더 이상 없음.`
- `14:20 공급 압력 일시 변동 확인. 연결부 점검 후 재가동, 추이 관찰.`
- `B조 인계. 3번 피더 간헐 걸림 있어 다음 조 초반 재확인 요청.`

## 6. 이번 프로젝트에 권장하는 로그 단위

센서 샘플 한 행마다 작업일지 한 건을 만들지 않는다. 작업자가 센서 측정마다 글을 쓰는 것은 비현실적이고, 템플릿 문장이 과도하게 반복될 수 있기 때문이다.

다음 두 종류를 함께 만드는 방식을 권장한다.

1. **교대 로그**: `라인 × 설비 × 교대`마다 1건
2. **이벤트 로그**: 설비 경고·조정·중단·재가동 같은 사건마다 1건

센서와 작업일지는 `line_id`, `equipment_id`, `lot_id`, 시간 구간을 이용해 연결한다. 실제 원본에 어떤 식별자가 있는지 확인한 뒤 최종 연결 키를 정한다.

권장 컬럼은 다음과 같다.

| 컬럼 | 의미 |
|---|---|
| `log_id` | 작업일지 식별자 |
| `log_created_at` | 기록 시각 |
| `shift_date` | 작업일 기준 날짜 |
| `shift_code` | 근무조 또는 교대 구분 |
| `line_id` | 생산 라인 |
| `equipment_id` | 설비 식별자 |
| `lot_id` | 작업 로트, 없는 기록은 결측 허용 |
| `log_type` | 시작점검·인수인계·생산실적·이상·정비 구분 |
| `note_text` | 작업자가 관찰한 현상과 상태 |
| `action_text` | 확인·조정·교체·재가동 등 수행 조치 |
| `downtime_minutes` | 설비 중단시간, 해당하지 않으면 0 또는 결측 |
| `writer_role` | 작업자·조장·보전·품질 등 역할 |
| `source_type` | 합성 데이터임을 나타내는 `synthetic` 값 |

## 7. 합성 작업일지 생성 시 금지할 사항

- 정상·불량 라벨 또는 세부 결함명을 입력으로 사용해 문장을 만들지 않는다.
- 불량 샘플에만 특정 단어가 나타나도록 설계하지 않는다.
- 검사 완료 후에만 알 수 있는 정보를 작업 시점의 일지에 넣지 않는다.
- 센서 샘플마다 문장을 한 건씩 만들지 않는다.
- 동일 문장 템플릿이 학습·검증·테스트 데이터에 그대로 반복되지 않게 한다.
- 합성 데이터를 실제 작업자가 작성한 기록이라고 표현하지 않는다.

## 8. 다음 확인 사항

1. 원본 데이터의 실제 시간 컬럼과 샘플 간격
2. 라인·설비·로트·작업지시 식별자의 존재 여부
3. 센서 파일과 이미지·라벨 파일을 연결하는 키
4. 데이터가 포함하는 날짜 범위와 교대조를 만들 수 있는 시간 정보
5. 실제 이상 판정 시점보다 앞서 사용할 수 있는 정보의 범위

이 내용을 확인한 뒤 합성 로그의 건수, 교대 체계, 사건 발생 빈도와 결측·중복·표기 변형의 수준을 정한다.
