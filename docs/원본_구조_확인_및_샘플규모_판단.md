# 원본 구조 확인 및 합성 샘플 규모 판단

## 1. 확인 목적

SMT 센서 원본에서 작업일지와 연결할 시간·설비·라인·로트 식별자가 존재하는지 확인하고, 2026년 10월 18일 마감 일정을 고려해 합성 데이터의 적정 크기를 결정한다.

이번 확인은 ZIP 내부 파일을 읽기 전용으로 검사했다. 원본 파일을 압축 해제하거나 수정하지 않았다.

## 2. 원본 데이터 규모

| 구분 | 원천 XLSX | 라벨 JSON |
|---|---:|---:|
| Training | 24,738개 | 24,738개 |
| Validation | 3,092개 | 3,092개 |
| 합계 | 27,830개 | 27,830개 |

- 원천과 라벨은 파일명 stem을 기준으로 27,830건 모두 일대일 대응한다.
- 원천에만 있거나 라벨에만 있는 stem은 0건이다.
- 중복 stem은 원천과 라벨 모두 0건이다.
- XLSX 한 파일은 헤더 1행과 센서 측정 5행, 총 6행 6열로 구성된다.
- 센서 측정은 전체 139,150행이다.

## 3. 확인된 스키마

### 3.1 원천 XLSX

모든 대표 아카이브에서 다음 6개 컬럼과 동일한 5초 시퀀스 구조를 확인했다.

1. `timestamp`
2. `temperature(°C)`
3. `humidity(%)`
4. `vibration(m/s²)`
5. `acceleration(g)`
6. `noise(dB)`

### 3.2 라벨 JSON

상위 키는 다음과 같다.

- `categories`
- `images`
- `annotations`
- `sensor_data`

`sensor_data.sensor_sequence`에는 XLSX와 같은 센서값과 `defect_detected`가 포함된다. `images`에는 JPG 파일명이 기록되어 있지만 현재 로컬 데이터의 ZIP에는 실제 JPG가 없고 XLSX와 JSON만 있다.

## 4. 식별자 존재 여부

| 항목 | 결과 | 사용 판단 |
|---|---|---|
| 측정 시각 | 존재 | `timestamp`를 작업일지 연결 기준으로 사용할 수 있음 |
| 고유 샘플 식별자 | 명시적 컬럼은 없지만 파일명 stem이 고유함 | stem을 `sample_id`로 사용 가능 |
| 라인 식별자 | 파일명에 A·B·C·D 코드가 있음 | 데이터 설명에서 의미가 확인되기 전에는 실제 라인이라고 단정하지 않음 |
| 설비 식별자 | 없음 | 합성 필드로 생성해야 함 |
| 로트 식별자 | 없음 | 합성 필드로 생성해야 함 |
| 교대조 | 없음 | timestamp를 기준으로 합성 가능 |
| 작업지시 | 없음 | 합성 필드로 생성 가능 |

파일명은 `SD_DEF_NM_A_20250807-100037_00003`과 같은 형태다. 상태, 결함 코드, A~D 코드, 시각, 순번을 포함한다. A~D 코드의 정확한 의미가 설명서로 확인되지 않았으므로 우선 `source_group_code`처럼 중립적인 이름으로 보존한다.

## 5. 시간과 클래스 분포

- 전체 샘플: 27,830개
- 불량: 16,932개, 약 60.8%
- 정상: 10,898개, 약 39.2%
- Training 날짜 범위: 2025-08-06 09:01:22 ~ 2025-09-06 16:33:45
- Validation 날짜 범위: 2025-08-11 16:35:26 ~ 2025-09-06 17:49:46
- 가장 작은 층: 정상·오삽 278개
- 가장 큰 층: 불량·밀림 2,346개

12개 결함 유형과 정상·불량 조합을 합친 24개 층의 분포가 불균형하므로 단순 무작위 추출보다 `제공 분할 × 정상/불량 × 결함 유형` 층화 추출이 필요하다.

## 7. 데이터 크기 판단

### 7.1 행의 단위부터 구분

원본은 샘플 하나가 5개의 센서 측정행으로 구성된다.

| 기준 | 10,000 | 15,000 | 20,000 |
|---|---:|---:|---:|
| 샘플 단위 데이터 | 10,000개 | 15,000개 | 20,000개 |
| 장기형 센서 측정행 | 50,000행 | 75,000행 | 100,000행 |

`15,000행`을 장기형 센서행으로 정의하면 실제 독립 샘플은 3,000개뿐이다. 초기 검토에서는 15,000개 샘플을 권장했으며, 최종 결정에서는 현실적인 비정형 수를 표현하기 위해 **15,132개 샘플**로 확정했다. 모델 입력용 표는 5초 시퀀스의 요약특징을 계산해 샘플당 한 행으로 구성한다.

### 7.2 후보 비교

| 크기 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 10,000개 | 생성·검증이 빠름 | 가장 작은 층이 약 100개로 줄어 세부 집단 검증이 불안정함 | 이진 이상탐지만 빠르게 수행할 때 가능 |
| 15,000개 | 전체 분포를 유지하면서 시간과 작업량을 절충함 | 세부 결함별 테스트 표본은 여전히 작음 | 권장 |
| 20,000개 | 세부 층의 표본을 더 많이 유지함 | 마감 전 텍스트 생성·검증·보고서 작업량이 증가함 | 결함 유형 분류까지 필수일 때 고려 |

이번 프로젝트의 주목적이 12개 결함 유형 분류가 아니라 정상·이상 탐지라면 약 15,000개가 충분하다. 10,000~20,000개라는 사용자 제안 범위는 타당하며, 최종 규모 15,132개는 마감 일정과 분포 보존을 함께 고려한 적정 범위에 포함된다.

## 8. 권장 추출과 분할

최종 데이터는 약 8:1:1로 분할한다. 15,132개는 10으로 나누어떨어지지 않으므로 가장 가까운 정수 배분인 12,106:1,513:1,513을 사용한다. 원래 Training에서는 학습·검증용 13,619개를 추출하고 원래 Validation에서는 테스트용 1,513개를 추출한다.

| 용도 | 출처 | 권장 샘플 수 |
|---|---|---:|
| 학습 | 원래 Training | 12,106 |
| 검증 | 원래 Training | 1,513 |
| 테스트 | 원래 Validation | 1,513 |
| 합계 |  | 15,132 |

표본은 제공 분할 안에서 정상·불량, 결함 유형, A~D 원본 코드의 비율을 고려해 층화 추출한다. 하나의 원본 시퀀스는 한 분할에만 사용한다.

텍스트나 합성 로트가 여러 샘플에 연결되므로 같은 `log_id`, `lot_id`, 작업일지가 서로 다른 분할에 걸치지 않게 그룹 단위로 분할해야 한다.

## 9. 권장 합성 방식

센서 컬럼을 각각 독립적으로 난수 생성하면 센서 간 상관관계와 5초 시퀀스의 형태가 무너질 수 있다. 마감 일정을 고려해 다음 방식을 권장한다.

1. 24개 층에서 실제 5행 센서 시퀀스를 통째로 층화 재표본한다.
2. 센서별 원래 범위와 분포를 벗어나지 않는 작은 잡음을 추가한다.
3. 원본의 5초 내 변화량과 센서 간 관계가 유지되는지 검증한다.
4. 통합에 필요한 최소 합성 식별자인 `equipment_id`, `lot_id`와 교대 정보인 `shift_date`, `shift_code`를 생성한다.
5. 작업일지는 정상·불량 라벨이 아니라 센서 상태와 별도의 설비 사건 규칙을 이용해 생성한다.

작업일지는 샘플마다 15,132건을 만들지 않는다. 교대 단위 로그와 사건 단위 로그를 생성한 뒤 여러 샘플에 연결한다. 따라서 텍스트 생성량은 전체 샘플 수보다 훨씬 작게 유지할 수 있다.

## 10. 전처리가 필요하도록 만드는 방법

프로젝트는 다음 흐름으로 진행한다.

1. 전처리가 필요한 센서 합성 데이터와 작업일지 합성 데이터를 만든다.
2. 센서와 작업일지를 통합한다.
3. 통합 합성 데이터를 전처리한다.
4. 전처리 전후의 품질 지표와 분포를 비교한다.

행 단위 정답 데이터와 오류 위치별 manifest는 만들지 않는다. 대신 `합성데이터_오류설계.md`에 오류를 넣은 근거, 생성 방법, 계획 비율과 실제 생성 건수를 기록한다. 재현성을 위해 생성 코드와 랜덤 시드는 보존한다.

포함할 품질 문제는 다음과 같다.

### 정형·시계열

- 일부 센서값 결측
- 실제 범위를 고려한 센서 스파이크와 경계 이상치
- 중복 샘플 또는 일부 중복 측정행

### 텍스트

- 작업일지 결측과 중복
- 띄어쓰기와 종결 표현 차이
- 설비 명칭과 약어의 표기 변형
- 일부 오탈자와 불필요한 특수문자
- 동일 의미 문장의 다양한 표현

### 모달리티 연결

- 작업일지 시각과 센서 구간의 작은 불일치
- 일부 작업일지의 설비 또는 로트 키 누락
- 하나의 교대 로그가 여러 샘플에 연결되는 일대다 관계

숫자의 문자열 변환과 날짜·시각 표기 혼합은 제외한다. 라벨 반전이나 결함 유형 오표기도 만들지 않는다. 라벨은 전처리 검증과 모델 평가의 기준이므로 깨끗하게 유지한다.

## 11. 일정 판단

2026년 10월 18일 마감을 기준으로 15,132개 샘플은 현실적인 규모다.

1. 10월 14일: 원본 구조·분포 확인과 합성 규칙 확정
2. 10월 15일: 깨끗한 합성 데이터와 작업일지 생성, 분포 검증
3. 10월 16일: 품질 문제 주입과 전처리 전 프로파일링
4. 10월 17일: 전처리, 전후 비교, 선택적 기준 모델 실행
5. 10월 18일: 결과 검토와 보고서·산출물 정리

LLM으로 작업일지 15,132건을 한 건씩 생성하지 않고, 검증된 문장 템플릿과 규칙 기반 조합을 사용하면 생성 시간은 큰 문제가 되지 않는다.
